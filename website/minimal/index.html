nvmr

Every nvm command. None of the wait.

A native drop-in for nvm v0.40.8, written in Rust. Same nvm command, same output and exit codes, same .nvmrc and ~/.nvm. Nothing to learn, nothing to migrate.

Install

Requires a Linux host with Docker. Run from the repository root:

docker build -t nvmr-dev docker
scripts/d.sh sh /src/scripts/bundle.sh
NVMR_BUNDLE="dist/nvmr-linux-$(docker run --rm nvmr-dev uname -m)" sh install.sh

Open a new shell, or load it into the current one:

export NVM_DIR="$HOME/.nvm"
. "$NVM_DIR/nvm.sh"

The installer copies nvm.sh, nvmr, nvmr-fetch, nvm-exec, bash_completion and nvm.fish into $NVM_DIR. It adds a profile line if one is missing and installs fish integration into conf.d when fish is present.

Installed Node versions and aliases are kept. Existing upstream integration files are overwritten, so back them up first if you want to roll back.

Installer variables

VariableEffect
NVMR_BUNDLEInstall from a local bundle directory.
NVMR_URLDownload nvmr-<os>-<arch>.tar.gz from this base URL.
NVM_DIRInstall directory. Default: $XDG_CONFIG_HOME/nvm if set, else ~/.nvm.
PROFILEProfile file to edit. /dev/null skips POSIX profile edits.

Usage

nvm install --lts          # install and use latest LTS
nvm use 22                 # switch to installed 22.x
nvm alias default 22       # default for new shells
nvm current                # active version
nvm ls                     # installed versions and aliases
nvm exec 22 node app.js    # run a command under 22.x

Per-project version:

echo 22 > .nvmrc
nvm install
nvm use

Commands

<version> is a full or partial version (22, v20.11), a built-in alias (node, stable, system, lts/*, lts/<name>) or a user alias. Commands that take an optional version read .nvmrc when it is omitted.

CommandDescription
install [<version>]Download and install. Flags: -s, -b, --lts[=name], --reinstall-packages-from=, --latest-npm, --skip-default-packages, --offline, --no-progress, --alias=, --default, --save
uninstall <version>Remove a version. Accepts --lts[=name].
use [<version>]Put a version on PATH. --silent, --lts[=name], --save
exec [<version>] <cmd>Run a command under a version.
run [<version>] [<args>]Run node under a version.
currentActive version, resolved through $PATH.
ls [<version>]Installed versions. --no-alias, --no-colors
ls-remote [<version>]Available versions. --lts[=name]
version <version>Resolve to one local version.
version-remote <version>Resolve to one remote version.
which [<version>]Path to the node binary.
alias [<name> <version>]List aliases, or set one.
unalias <name>Delete an alias.
deactivateUndo nvm's changes to this shell.
unloadRemove nvm from this shell.
reinstall-packages <version>Reinstall global npm packages from another version.
install-latest-npmUpgrade npm on the current version.
cache dir / cache clearShow or empty the download cache.
set-colors [<codes>]Set output colours (default bygre).

Full reference: nvm --help or src/help.txt.

Configuration

Set these before sourcing nvm.sh.

SettingEffect
NVM_LAZY=1Defer auto-use until the first call to nvm, node, npm, npx, corepack, yarn or pnpm. In fish, skips auto-use at startup.
NVM_LAZY_PATH=1With lazy mode: set PATH directly when the default alias names an installed exact version.
--no-use. "$NVM_DIR/nvm.sh" --no-use loads without selecting a version.
NVM_NO_SOURCE_FALLBACK=1Make install binary-only by default.

All other upstream variables (NVM_NODEJS_ORG_MIRROR, NVM_DIR, etc.) behave as in nvm v0.40.8.

Compatibility

  • Stdout, stderr, exit codes and resulting shell environment are diffed against upstream nvm for every scenario in the test suite.
  • Deliberate deviations are documented in spec §12.
  • Known differences are listed in spec §15.
  • Existing io.js and pre-0.12 Node installs can be listed, resolved, used and uninstalled. New io.js installs are not supported.

Design

ComponentRole
nvm.sh, nvm.fishThin shell function. Runs nvmr and applies the environment changes it emits.
nvmrAll command logic: resolution, aliases, PATH. Links only libc.
nvmr-fetchHTTPS, checksum verification, extraction. Separate binary, kept off the switching path.
nvm-execLaunches a command with a selected environment.

A child process cannot modify its parent's environment, so a shell function remains necessary. Everything else is native.

Development

docker build -t nvmr-dev docker
scripts/d.sh cargo build --release
scripts/verify.sh

scripts/verify.sh runs rustfmt, clippy (-D warnings), unit tests and the full upstream parity suite, including real downloads, interrupted installs, colour output, all shells and POSIX portability.
