Get up and running.

On a Linux host with Docker running, build the bundle from your checkout and install it into your nvm directory.

Already using nvm?

Your Node versions and aliases stay in $NVM_DIR. The installer replaces the integration files and reuses your existing profile entry.

From the repository root · Linux bundle

docker build -t nvmr-dev docker
scripts/d.sh sh /src/scripts/bundle.sh

NVMR_BUNDLE="dist/nvmr-linux-$(docker run --rm nvmr-dev uname -m)" sh install.sh

Then open a new terminal. Inspect the installer.

A small field guide.

Install a version, switch projects, carry on. All commands run through the nvm shell function after installation.

nvm install --lts
Install and use the latest LTS.
nvm use 22
Switch to an installed Node 22.
nvm ls
List installed versions and aliases.
nvm current
Show the active Node version.
nvm exec 22 node app.js
Run a command with a chosen version.
nvm alias default 22
Choose the version for new shells.
nvm --help
Read the complete command reference.

Let the project choose.

echo "22" > .nvmrc
nvm install
nvm use

Commit .nvmrc alongside your code. The version follows the project.

Prefer the name nvmr?

alias nvmr='nvm'
nvmr use 22

Add the alias after loading nvm in your shell profile. Both names reach the same implementation; existing nvm scripts keep working.

Built around the fast path.

Everyday commands go through a native Rust core. Downloads and extraction live in a separate process, keeping that machinery off the version-switching path.

A thin shell function applies the environment changes where they belong: in your current shell.

Keep your setup.

Compatibility is the point: familiar commands, output, exit codes, and the same on-disk layout.

The reference is nvm-sh/nvm v0.40.8. This is an independent Rust implementation.

Read the compatibility spec ↗
Will I need to reinstall Node?

The installer shares your existing $NVM_DIR, including versions and aliases. It copies the native binaries and shell integration into that directory. Keep a backup of your previous integration files if you want to restore them later.

Which shells work?

bash, zsh, dash/POSIX sh, and fish. The installer adds profile lines for POSIX shells when needed and installs fish integration into conf.d when fish is available.

Is there a lazy mode?

Set NVM_LAZY=1 before loading nvm.sh to defer automatic version selection until first use of nvm or a Node command. Fish skips startup auto-use in lazy mode; run nvm use yourself.

What are the current limits?

Linux has been built and tested in Docker. macOS is a target and has not yet been built or tested. Windows/MSYS, SunOS, AIX, and BSD are outside the current scope. Installing io.js is unsupported; existing io.js and old-layout Node installs are recognized. The known edge-case differences are documented in the specification.

Why the nvm command?

nvmr is the canonical project name. Keeping the shell function named nvm preserves existing commands and scripts. The optional nvmr alias above gives you the branded spelling too.
